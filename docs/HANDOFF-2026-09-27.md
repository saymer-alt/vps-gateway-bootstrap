### 5.1 Capabilities (C3-C8 remaining)

Exact-set model: the plan's required capability set is **derived** by
compiled code from validated typed plan actions (`RequiredCapabilities(plan)`
— C3), serialized canonically (`name.vN;k=v;...`, parameters sorted, sets
sorted-unique, canonical decimals/CIDRs), and compared for **exact equality**
against the signed set in the approval envelope. No superset, no missing, no
duplicates, no unknown names. Approval schema v2 adds `Purpose`
(composition ID) and makes the capability set explicit (empty only for
NO_CHANGE). v1 and v2 verifiers stay isolated; no dual-schema acceptance.
Under lock, derivation must be byte-identical or the run fails
(`CAP_DERIVATION_STALE`). Compositions v1: `MUVG_INTEGRATION_V1` (one
transaction: project files + scoped sysctl drop-in AND runtime values +
reserved-table rule/route + mandatory bypass firewall rule + optional MSS;
forbidden families: SSH, installer, reboot, any service, any Mihomo/AWG
action, deletion) and `MUVG_FILES_REFRESH_V1` (already-owned project files
only; no service restart, no network state, no sysctl drop-in).

### 5.2 Ownership (O2-O11 remaining)

Verdict vocabulary and precedence are implemented (O1). Remaining: O2
compiled birthright policy table (the O1 classification is the seed); O3
state schema v2 with `Evidence[]` (`ResourceIdentity + SpecHash +
EvidenceRef{TxID, PlanFingerprint, HostIdentity}` — v1 readers refuse v2
files; no migration manufactures ownership); O4 journal corroboration
(COMPLETED + non-rolled-back transaction binding the same
identity/fingerprint/host); O5/O6 the per-resource admission evaluator
(**closes P1-A**); O7 integration with capabilities/composition; O8 approval
wiring; O9 under-lock full admission; O10 evidence minting with
journal-COMPLETED-before-state-save ordering; O11 recovery/decommission.
Evidence loss downgrades to UNPROVEN; shape equality never proves ownership;
NO_CHANGE never mints; ACCEPT_CURRENT is forbidden on UNSAFE/UNKNOWN states.

### 5.3 Direct leak (D3-D8 remaining)

The pure evaluator core is implemented (D1/D2). Remaining: D3 doctor
integration (present the assessment; never print repair commands), D4
SourceSelector integration, D5 bypass-loop evaluator (needs F5), D6-D7
validate/production semantics (production fails on UNKNOWN/DEGRADED with
MUVG intent; foreign UNSAFE routing also fails — machine safety is
ownership-independent), D8 disposable-VPS validation. Empirical items

### 5.4 Mihomo/TUN discovery (M1-M6 remaining, none implemented)

Contracts: MUVG v1 supports ONLY host-systemd Mihomo. Correlation
(`MIHOMO_TUN_CORRELATED`) requires all of: unit active, config provenance
resolved from the unit ExecStart (`-d`/`-f` only), `tun.enable: true`,
explicit `tun.device`, live interface with that name and Kind "tun", config
mtime <= process start, optional operator assertion equal. `auto-route`
must be explicitly false (true or unknown BLOCKS). Secret boundary: retain
only `tun.enable/device/auto-route`, `tun.stack`, top-level `ipv6`,
`auto-detect-interface`; never proxies, providers, credentials, controller
secrets, or whole files. `tun.device` omitted and `auto-route` omitted both
block (fail closed). YAML parsing must be a strict subset parser that fails
closed on anchors/aliases/flow/multi-doc touching relevant keys (NIGHT-11
decision D3: hand-rolled subset preferred over adding a YAML dependency).

### 5.5 AWG SourceSelector (A1-A6 remaining, none implemented)

Selector semantics: the IPv4 source prefix of decrypted client traffic at
the host policy-routing decision — for bridge-networked AWG containers the
Docker network IPAM subnet (post-container-NAT, pre-host-masquerade).
`discovered-awg` requires: unique strong candidate (Amnezia-pattern image
AND published UDP port AND attachment), running, single unambiguous IPv4
pool (multi-pool resolvable only by the container's observed address), no
overlap with host networks, and the L4 proof: `ip route get <dst> from
<in-subnet> iif <bridge>` resolving into the expected table. Multi-network
and multiple candidates are ambiguous (explicit mode or rejection).
Correlation via `docker network inspect <network-ID>` (validated hex argv;
preferred over container inspect because network output carries no Env).
Encrypted-transport loop safety is a separate fact (bypass mark) whose
marking mechanism is NOT observable without rule-level firewall discovery.

### 5.6 Firewall rule-level + loop proof (F1-F12 remaining, none implemented)

`LOOP_SAFE` requires the full positive chain: transport identity (UDP
sport = the AWG listen port on the bridge interface, pre-masquerade) →
reachable mangle-PREROUTING (bridge) or mangle-OUTPUT (host-native) rule
covering all transport variants → mark assignment (normalized
xmark value/mask; CONNMARK restore only with a proven reachable restore
path) → no later overwrite on any reachable path → semantic equivalence to
the RPDB bypass rule (`(mark & mask) == value`) → bypass rule priority
strictly before the selector rule → consistent snapshot. Routing inventory
alone must NEVER produce LOOP_SAFE. A firewall `LOOP_RISK`/`LOOP_UNKNOWN`
blocks MUVG planning that depends on loop exemption.

### 5.7 Sysctl (S5-S10 remaining; S1-S4 implemented)

S5: effective-state evaluator combining the runtime and persistence planes
into per-key state with persistence confidence (STATIC_CONFIDENT requires:
project drop-in proven, winning precedence resolution, no higher-precedence
conflict, key supported, boot mechanism known — empirical reboot proof is
separate). S6: doctor/validate integration (production fails on UNKNOWN
viability with MUVG intent). S7-S9: ownership/capability integration,
bounded `/proc/sys` runtime writes (direct leaf writes only — never
`sysctl --system`; apply `ip_forward` first because changing it may reset
other IPv4 parameters), rollback (runtime old value + file manifest as
separate checkpointed actions). S10: disposable-VPS validation. The
`/etc/sysctl.conf` ordering position is an explicit empirical gap.

### 5.8 Recovery (R1-R12 remaining, none implemented)

Per-action durable progress states (`PLANNED → BACKUP_DURABLE →
MUTATION_STARTED → MUTATION_DURABLE → VALIDATED → ROLLBACK_STARTED →
ROLLBACK_DURABLE | FAILED`) — after any crash, recovery must never guess
whether an action happened; the triad is progress marker + idempotent
rediscovery + backup manifest. Typed plan summary in the journal (spec
hashes, resource identities, capability-set hash, composition ID, safety
hash — never raw specs or secrets). Recovery state machine R0-R6
(detect/inspect/classify/authorize/execute/verify/close) with resolution
classes ABANDON / COMPLETE_ROLLBACK / ACCEPT_CURRENT; ACCEPT_CURRENT is
forbidden on UNSAFE/UNKNOWN machine states; recovery authorization is
purpose-bound, single-use, two-phase (intent/outcome) with the same trust
anchor. **R1-R6 are prerequisites for generalized mutation** (they close
P1-B). Known crash window in the current code: state is saved BEFORE the
journal reaches COMPLETED; the recommended fix is journal-terminal-first
ordering.
