# P1-B (offline slice): exact v2 approval admission before any privileged broker

Date: 2026-11-07. Baseline: `7af31921154d3fc44e88a5059cdb0a25f748ba49`. Follows [P0/P1 #72](https://github.com/saymer-alt/vps-gateway-bootstrap/pull/72) and [P1-A #73](https://github.com/saymer-alt/vps-gateway-bootstrap/pull/73). Core MVP tracked in [Issue #56](https://github.com/saymer-alt/vps-gateway-bootstrap/issues/56).

**Status: synthetic code/unit tests ONLY — NOT a root broker, NOT wired to runtime, NOT operator ceremony or lab acceptance.**

A small, verifier-only package `internal/brokeradmission` composes existing security primitives: `brokerproto.Decode` (strict untrusted wire), `approval.Verifier.VerifyV2` (real Ed25519, canonical payload, expected `SERVICE_EXPERIMENT_V1` purpose, host machine-id, exact trusted plan fingerprint and expiry), `approval.GrantedCapabilities` and `capability.VerifyCapabilityGrant` (exact rather than subset match). It never accepts a caller-selected service name or required capability: the sole compiled allowed resource remains `fail2ban.service`. A verified signature is necessary but not sufficient for any real action.

**Critical provenance:** `verifier` and `trustedPlanFingerprint` parameters are **trusted-broker inputs only**. The package does not obtain authenticated peer identity, trusted discovery, a Plan, policy/ownership, a protected anchor, or a privileged execution context. No agent-facing caller may set the anchor, expected host, plan fingerprint or capabilities. The underlying local trust anchor is not resistant to an attacker with unrestricted root; see [synthetic key replacement #71](https://github.com/saymer-alt/vps-gateway-bootstrap/pull/71). A future broker MUST derive those trusted inputs independently, keep the agent non-root, and enforce remaining staleness-under-lock, transaction journal, rollback, management and existing experiment gates.

Negative tests use **only deterministic synthetic Ed25519 keys** and fixed local time: wrong signer, plan, verifier/approval host, expiry, purpose, grant (including a different systemd unit), overgrant, tampering, missing anchor, v1-to-v2 downgrade, a correctly signed but noncanonical capability list, untrusted wire authority fields, unknown operation and missing fingerprint. The positive test proves cryptographic admission, **not privileged execution**. No real private key, network endpoint, systemd, VPS or production host path is accessed.

After this offline slice, the remaining actual P1-B integration must be separately owner-reviewed before any broker socket/root service. `--confirm` legacy G1, ownership G2, composition G3, real signing ceremony, OS peer authentication and disposable system-lab acceptance all remain **OPEN / NOT PRODUCTION READY**. CI PASS is limited to code and regression tests.
