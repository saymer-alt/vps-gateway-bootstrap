## B. Binding architecture

The pipeline is the read-only plan builder followed by the orchestrated
mutation boundary:

```text
DISCOVER → MODEL → PLAN → CONFIGURE → VALIDATE → READY      (read-only)
OPERATOR CONFIRMATION (the mutation boundary)
LOCK → BACKUP → APPLY → VALIDATE → RE-DISCOVERY → FINAL VALIDATION
→ CONVERGENCE → PERSIST                                     (orchestrated)
```

Core invariant: **a diff alone is not permission.** Mutation requires a
concrete typed Plan, operator confirmation bound to its exact SHA-256
fingerprint, executor coverage, preflight, a fresh staleness re-check under
the machine lock, a durable journal record begun before the first mutation,
and persistence only after re-discovery, final validation and convergence
succeed. Everything else in this document details how that invariant is
currently kept — and where its future generalization is deliberately
blocked.

## D. Current transaction semantics

- **Lock**: one compiled project identity, `/etc/vps-gateway/apply.lock`
  (flock-based on Linux; crash-safe). Acquired after confirmation, before
  journal Begin; held for the whole transaction. Not caller-configurable —
  the `apply` CLI exposes no lock-path flag (fixed in `bb99a74`; the
  `Orchestrator.LockPath` struct field remains as a test seam only).
  Acquisition failure blocks pre-mutation. Mutual exclusion cannot be
  bypassed by choosing alternate paths.
- **Journal** (`internal/journal`): every mutating transaction writes a
  durable record (atomic + fsyncs) **before** the first possibly mutating
  operation: transaction id, plan fingerprint, approval evidence, per-action
  retry classes, `MutationPossible`. The terminal outcome
  (`COMPLETED`/`FAILED`/`RECOVERY_REQUIRED`) is written by a deferred
  finalizer; since `f50e226` the `Execute` result values are **named**, so a
  failed terminal write is visible to the caller (both CLIs exit non-zero on
  a COMPLETED outcome carrying blockers) — the earlier false-success defect
  is fixed and regression-proven. In-progress records that never reach a
  terminal outcome are crashed runs and fail-safe the next invocation.
- **State** (`state.SaveModel`): written only from verified post-change
  state (atomic 0600, schema-version guards against downgrade-overwrite),
  and only after re-discovery + final validation + convergence + the
  anti-laundering journal gate. `apply` never reads persisted state.
- **Backup/rollback**: transaction-scoped, manifest-bound
  (`<backup-root>/<tx>/<action>/`, content-first manifest-last, digests,
  verify-before/after restore); reverse-order rollback on any failure;
  `ROLLBACK_FAILED` (or failure on a no-autonomous-retry action) latches
  `RECOVERY_REQUIRED`.
- **Known residual ordering**: state persistence still happens **before**
  the deferred journal terminal record (`state persistence → journal
  COMPLETED`). This is an unresolved architectural/recovery concern (the
  designed journal-terminal-first ordering, HANDOFF 2026-09-27 §5.8): its
  effect is a safe-stop with a confusing diagnosis (state updated, journal
  says crashed), not an authority risk — under the claim-then-corroborate
  ownership design (§E/G) it can only downgrade ownership, never upgrade
  it.

## E. Current PURE foundations (implemented, tested, zero production
importers — none of them grants authority)

- **`internal/capability`** (C1/C2): closed five-capability vocabulary
  (`muvg.projectfile.v1`, `muvg.sysctl.apply.v1`, `muvg.routing.reserve.v1`,
  `muvg.firewall.tagged.v1`, `muvg.firewall.mssclamp.v1`) with compiled
  parameter schemas, byte-exact canonical parsing, typed derivation
  constructors, and conflict-rejecting aggregation. Compiled namespace
  constants: chains `vpsgw_`, tag `muvg` (provisional — operator decision
  L1). Plan-to-capability mapping (C3-A) has since LANDED as
  `internal/planmap` (see its §J block). **C4 landed** (PURE
  capability-grant verification, ZAI-27): `VerifyCapabilityGrant(required,
  granted CapabilitySet) GrantVerification` checks EXACT-SET equality
  between the canonical required set (e.g. C3-A output) and a canonical
  granted set supplied as typed input. Contract source: the decided
  approval architecture (docs/security-model.md §6/§9C — the approval
  binds "the named capability set the plan exercises" to the exact plan,
  so "the operator approved plan F" means "granted capabilities {…} to
  this exact action set") and the O6-B audit admission equation ("C3-A
  derived == approval-granted, exact set"). Closed result vocabulary
  SATISFIED/MISMATCH (deliberately authority-free naming); mismatches are
  inspectable as canonical `Missing` (= Required − Granted) and
  `Unexpected` (= Granted − Required) sets, freshly allocated and
  canonical-ordered — over-granting is itself an authorization mismatch
  ({}/{A} is MISMATCH, never satisfied). Exact equality is canonical-ID
  identity: same vocabulary name with different parameters is a mismatch
  showing both directions. Error vs mismatch is structural: invalid
  members, duplicates and name-level parameter conflicts fail at set
  construction (C1/C2 classes), so the verifier is TOTAL over valid sets
  — a missing requirement is never a parser error; no partial-satisfaction
  status exists. Required and Granted are structurally distinct inputs; no
  helper derives a grant from a required set (no-self-grant tripwire
  `TestVerifyNoSelfGrantStructure`), and the verifier consumes no
  approval/ownership/safety/executor/recovery plane and no I/O (purity
  tripwire `TestVerifyImplementationIsPure`). Zero production consumers:
  no authenticated production grant source exists (approval-v2 and the
  operator decisions G2/G4 remain open), so SATISFIED never means
  "authorized".
- **`internal/ownership`** (O1 + O5-A): closed 8-verdict vocabulary
  (UNDETERMINED > CONFLICT > COLLISION > GONE > OWNED_DRIFT > UNPROVEN >
  OWNED_VERIFIED > ABSENT), typed `ResourceIdentity` per class, compiled
  birthright namespaces, non-authoritative `StateEvidence`/`EvidenceRef`/
  `SpecHash` claim types. Legacy config labels (OWNED/EXTERNAL/UNKNOWN) are
  not verdicts and have no conversion path. **O5-A landed** (PURE evidence
  verification): `Corroborate(VerificationInput) (Verification, error)`
  checks a persisted evidence claim against typed durable transaction facts
  — exact transaction-action membership, COMPLETED-without-rollback-or-latch
  terminal state, host/past+present/fingerprint/spec-hash bindings — and
  fails closed on every mismatch, absence, ambiguity and unknown value.
  Verified means *suitable to be considered for admission*; it is not an
  ownership verdict and not mutation authority. The journal implementation
  is deliberately not imported (vocabulary mirrored; adapter is O5-D).
  The 2026-09-29/30 real-fleet lessons (scoped sysctl reconciliation after
  the rp_filter outage, dual UDP service-port allocations as distinct
  identities, external-manager ownership by 3X-UI/Amnezia/Xray/Docker/UFW,
  per-interface end-to-end IPv6 health) were considered for this design and
  deliberately NOT converted into ownership facts: OBSERVED !=
  OWNED_VERIFIED, DESIRED != OWNED_VERIFIED, PERSISTED != OWNED_VERIFIED,
  MATCHING CONTENT != OWNED_VERIFIED, PROJECT-LIKE NAME != OWNED_VERIFIED.
  **O5-B landed** (PURE live+evidence verdict derivation):
  `DeriveVerdict(DerivationInput) (Derivation{Verdict, Reasons}, error)`
  combines the O5-A corroboration result with typed injected live facts
  (`LiveFact{State: PRESENT/ABSENT/UNKNOWN, SpecHash, ExternalOwner}`) and
  the compiled birthright contract into one O1 verdict per resource:
  verified evidence + matching live → OWNED_VERIFIED; verified + changed
  file → OWNED_DRIFT; verified + changed network object or positively
  established external manager → CONFLICT; verified + proven absence →
  GONE; present without verified evidence → UNPROVEN, or COLLISION inside
  a birthright namespace; proven absence without verified history → ABSENT;
  any UNKNOWN live state → UNDETERMINED (never ABSENT/GONE); spec
  fidelity unobservable for a class → UNDETERMINED. A verdict is
  classification only — never mutation authority, never adoption, never
  repair permission (purity tripwire `TestDeriveImplementationIsPure`;
  zero production importers).
- **`internal/sysctl`** (S1–S4): bounded `/proc/sys` runtime reads over the
  compiled allowlist; strict persistence parsing of the ranked `sysctl.d`
  set plus the unranked `/etc/sysctl.conf` (explicit empirical-ordering
  uncertainty); per-key resolution. Strengthened in `10cdaac`: directory
  listing failures and sysctl.conf unsupported/unreadable states propagate
  as per-key uncertainty — a supported key can only resolve confidently
  when every source that could override it was successfully inventoried
  (UNKNOWN != absent). `EffectiveRPFilter` = max(all, interface), pinned.
  **S5 landed** (PURE effective-state evaluator, ZAI-26):
  `EvaluatePolicy(policy []PolicyRequirement, runtime []RuntimeObservation,
  resolution Resolution) (Evaluation, error)` answers, per
  compiled-allowlist key, what can be PROVEN about the effective sysctl
  state required by a safety policy. Typed inputs only — no I/O, no clock,
  no ownership/approval/capability/recovery plane (purity tripwire
  `TestEvaluateImplementationIsPure`; zero production consumers). Binding
  semantics: runtime and persistence are separate dimensions, never
  collapsed (OE-2); UNKNOWN never becomes SAFE or a value (absent
  observations, absent interfaces, collector failures, persistence gaps,
  DirErrors, unsupported constructs, sysctl.conf uncertainty); a persistent
  override of the project drop-in is judged by its ACTUAL effective value
  (override-to-unsafe = VIOLATED; override-to-same-safe = satisfied on the
  safety plane, separate from ownership/drift); for scoped
  `net.ipv4.conf.<iface>.rp_filter` the effective value max(conf.all,
  conf.<iface>) governs each plane and BOTH components must be proven in
  that plane (runtime-observed or durably declared and uncertainty-free);
  conf.default is never proof for an existing interface; absence of a
  conf.all declaration leaves the effective value UNKNOWN in both planes;
  advisory (non-required) keys are reported but never poison the combined
  required verdict. Result vocabulary: SATISFIED/VIOLATED/UNKNOWN per
  dimension with a closed machine-readable reason enum.
- **`internal/leak`** (D1/D2): the pure direct-leak evaluator over typed
  RPDB inventories. Strengthened in `0bfb29e`: SAFE is bounded to the
  supported topology envelope — rules carrying unmodeled selector/action
  keys (iif, suppress_*, not, ...) refuse the walk; multipath (nexthop)
  routes are flagged and never reduced to a single device; multiple
  defaults must agree or the table is ambiguous; a competing more-specific
  route in the selected table blocks SAFE; route-get evidence is
  authoritative in both directions; TUN liveness is mandatory; scope is
  IPv4-path only; no loop-safety claim is ever emitted (LOOP_SAFE is a
  separate unbuilt family).
- **`internal/fileobs`** (file-class live observation, ZAI-28 — the first
  slice of O6-B audit prerequisite 3 "live observation adapters per
  resource class"; NOT numbered O5-E, which is reserved for evidence
  minting/ordering): turns read-only file inspection into one typed fact
  per file-shaped resource identity.
  `ObserveFile(identity, kind, *Collector) (FileObservation, error)`
  layers a strictly read-only Linux collector (lstat → open
  O_RDONLY|O_NOFOLLOW → fstat → dev/ino identity check → read) under a
  PURE normalization with the closed status vocabulary
  PRESENT / PRESENT_INCOMPLETE (regular file observed, content unread —
  PRESENT-but-spec-unknown, never collapsed) / PRESENT_UNSUPPORTED
  (symlink — including broken — directory, FIFO, other: occupancy,
  fail-closed, never followed, never absent) / ABSENT (positively proven
  missing directory entry: ENOENT/ENOTDIR; permission errors, I/O errors
  and symlink loops NEVER produce it) / UNKNOWN. Live spec hash = the
  EXACT evidence contract `state.ActionSpecHash` (domain-separated
  canonical FileActionSpec JSON: path + content + permission bits), under
  the caller-supplied evidence action kind (CREATE_FILE/UPDATE_FILE — the
  kind participates in the domain), so the hash is directly comparable to
  state-v2 EvidenceRecord / journal-v2 Spec values; uid/gid are NOT part
  of a file spec (contract truth, not a choice made here). TOCTOU inside
  one pass is refused: a dev/ino change between lstat and open, a
  mid-pass disappearance, or a symlink swapped in (ELOOP under
  O_NOFOLLOW) all fail closed to UNKNOWN — no mixed observation can be
  fabricated; even a coherent observation remains a point-in-time fact,
  not a lease (the lifecycle lock does not serialize external writers),
  and no freshness/timestamp policy is modeled. Confinement is compiled:
  ClassFile inside `ownership.ProjectFileNamespace`, ClassSysctlDropIn
  exactly `ownership.ProjectSysctlDropInPath`, authority/lifecycle
  material (state.json, apply.lock, trust/, journal/, backups/) refused
  as structural errors; unsupported action kinds and invalid identities
  are structural errors, never statuses. `FileObservation.LiveFact()`
  translates to `ownership.LiveFact` without reparsing (richer statuses
  downgrade honestly: PRESENT_UNSUPPORTED/PRESENT_INCOMPLETE →
  LivePresent without hash, which downstream derivation fails closed on);
  ExternalOwner is never set here. Zero ownership/admission semantics:
  no verdict vocabulary, no minting, and zero production consumers
  (source tripwires pin the verdict-vocabulary ban and the read-only
  collector; a test-only composition feeds DeriveVerdict to prove type
  compatibility).

## J. Recommended next work

**Landed: O5-A, ownership evidence-verification primitive** (PURE, no
authority effect) — `internal/ownership/evidence.go`. API:
`Corroborate(VerificationInput) (Verification, error)` with
`VerificationInput{Claim StateEvidence, JournalResource string,
Candidates []TransactionFact, CurrentHost string}` and
`TransactionFact{TxID, PlanFingerprint, HostIdentity, Outcome,
RecoveryRequired, RollbackAttempted, RollbackResult, Actions[]}`. Result
vocabulary: `VERIFIED` / `MISMATCH` / `INCOMPLETE` (structurally invalid
input is an error) — deliberately not an ownership verdict. Legs, all
required and fail-closed: claim validity; exact transaction-action
membership (the claimed resource coordinate must appear APPLIED in the
transaction); COMPLETED terminal state with no recovery latch and no
rollback; host binding past (claim↔record) and present (record↔current
machine); plan-fingerprint binding; spec-hash binding when the
corroboration carries one (a v1 journal carries none, so its facts cap at
INCOMPLETE — the live spec comparison is O5-B). Journal vocabulary is
mirrored as closed constants, not imported (purity tripwire
`TestEvidenceImplementationIsPure`; zero production importers). P1-A
remains unresolved: nothing consumes Corroborate or DeriveVerdict yet
(only O5-B does, and it is itself unwired).

**Landed: O5-B, live+evidence verdict derivation** — see the ownership
foundation bullet in §E.

**Landed: R4-B, pure unresolved-transaction recovery classifier** — new
PURE package `internal/recovery` (`classify.go`): `ClassifyTransaction`
and `ClassifyJournal` classify typed mirrors of durable v1 journal records
into a closed recovery vocabulary — `COMPLETED` / `FAILED_RESOLVED` (every
action durably reverted, or proven never to have reached Apply) /
`FAILED_UNRESOLVED` (FAILED but some action reached Apply without durable
revert proof) / `RECOVERY_REQUIRED` / `IN_PROGRESS` (no terminal record —
always conservative: the v1 schema has no PREPARED-only phase, so a record
in progress can always mean mid-mutation interruption) / `INDETERMINATE`
(contradictory records for one transaction, COMPLETED carrying rollback
evidence or non-applied actions, FAILED carrying a failed rollback). Exact
duplicate records collapse; contradictory duplicates are INDETERMINATE —
never last-writer-wins (v1 provides no authenticated ordering). Machine-
readable reason codes (`Reason` enum) back every state; unknown future
vocabulary fails closed as invalid input. What v1 can prove: terminal
outcomes, per-action final statuses, rollback results. What it cannot
prove: per-action durable progress between Begin and the terminal write,
so an in-progress record can never be resolved without the operator, and
absence of records is never proof of no mutation (pinned as the
empty-history note). Classification is PURE and unwired; it grants no
authority — `RECOVERY_COMPLETED != MUTATION_ALLOWED`, and it neither
consumes nor affects ownership verdicts. The CODEX-02 deferred-
finalization concern's current verified status: fixed since `f50e226`
(`Execute` named results; terminal-write failures caller-visible), while
the state-persistence-before-journal-terminal ordering remains the open
designed change. P1-B remains unresolved until latch/admission/recovery
wiring consumes this layer.

**Operational invariants recorded (2026-10-01)** — the 2026-09-29/30
real-fleet findings are codified as binding architecture constraints in
`docs/OPERATIONAL-INVARIANTS-2026-10-01.md` (INV-OP-1..10: effective ≠
persistent, persistent ≠ ownership, disappearance ≠ restoration, equality
≠ provenance, heterogeneous fleet ≠ drift, UNKNOWN never collapses,
external resemblance ≠ adoption, presence ≠ reachability, recovery needs
project evidence, planes never launder one another). All are enforced or
contract-owned by existing PURE layers; the operational evidence confirms
O5-C as the next slice.

**Landed: O5-C, state schema v2 evidence reader** — `state.SchemaVersion`
is now **2** (writes); v1 documents remain readable but can never carry
evidence (an evidence key in a v1 document fails closed — readability is
never an evidence-authority upgrade). `Model.Evidence []EvidenceRecord`
holds durable ownership-evidence CLAIMS: identity (O1 `ResourceIdentity`
validation reused via the state→ownership import — one validation source,
no cycle), spec hash (canonical 64-char lowercase hex, never normalized),
TxID/plan-fingerprint/host-identity reference, minting timestamp. The v2
reader is strict: unknown fields rejected at every level, duplicate JSON
keys rejected at every level (token-walk — encoding/json last-write-wins
must never decide authority content), exact duplicate records rejected as
a writer bug, conflicting records preserved as distinct history (the
disagreement belongs to corroboration), missing/zero/malformed/future
