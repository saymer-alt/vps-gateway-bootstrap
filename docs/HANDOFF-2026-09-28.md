## B. Binding architecture

The pipeline is the read-only plan builder followed by the orchestrated
mutation boundary:

```text
DISCOVER → MODEL → PLAN → CONFIGURE → VALIDATE → READY      (read-only)
OPERATOR CONFIRMATION (the mutation boundary)
LOCK → BACKUP → APPLY → VALIDATE → RE-DISCOVERY → FINAL VALIDATION
→ CONVERGENCE → PERSIST                                     (orchestrated)
```

Core invariant: **a diff alone is not permission.** Mutation requires a
concrete typed Plan, operator confirmation bound to its exact SHA-256
fingerprint, executor coverage, preflight, a fresh staleness re-check under
the machine lock, a durable journal record begun before the first mutation,
and persistence only after re-discovery, final validation and convergence
succeed. Everything else in this document details how that invariant is
currently kept — and where its future generalization is deliberately
blocked.

**One sanctioned mutation path exists and nothing else:**

   `firstExperimentGuard` to exactly one action: `SERVICE
   service.fail2ban.service`, operation `restart`, expected `active`,
   ownership OWNED. Confirmation is the legacy fingerprint-prefix form
   (G1: self-suppliable by the invoker — experiment containment, not an

is intentionally disabled (2026-09-29 containment).** A CODEX TASK-02 audit
identified a narrowly reachable ownership-authority defect: the
experiment's embedded legacy OWNED label plus its shape-only guard never
established ownership provenance, so a foreign file independently created
at the pinned target could reach `FileExecutor` and be replaced (the P1-A
data flow, instantiated). The tool now refuses all mutating execution —
no confirmation is accepted, `orchestrate.Execute` is unreachable
(source tripwire `TestFileExperimentHasNoExecutePath`), and no lock,
journal, backup, or state write can occur from it. It retains discovery,
config assembly, diff, plan construction, fingerprinting, and preview
(`--dry-run` exits 0; any mutating attempt exits non-zero with a
containment notice). This is containment only: **architectural P1-A
remains unresolved** and the widening moratorium (§I) stands.

Everything else is

## D. Current transaction semantics

- **Lock**: one compiled project identity, `/etc/vps-gateway/apply.lock`
  (flock-based on Linux; crash-safe). Acquired after confirmation, before
  journal Begin; held for the whole transaction. Not caller-configurable —
  the `apply` CLI exposes no lock-path flag (fixed in `bb99a74`; the
  `Orchestrator.LockPath` struct field remains as a test seam only).
  Acquisition failure blocks pre-mutation. Mutual exclusion cannot be
  bypassed by choosing alternate paths.
- **Journal** (`internal/journal`): every mutating transaction writes a
  durable record (atomic + fsyncs) **before** the first possibly mutating
  operation: transaction id, plan fingerprint, approval evidence, per-action
  retry classes, `MutationPossible`. The terminal outcome
  (`COMPLETED`/`FAILED`/`RECOVERY_REQUIRED`) is written by a deferred
  finalizer; since `f50e226` the `Execute` result values are **named**, so a
  failed terminal write is visible to the caller (both CLIs exit non-zero on
  a COMPLETED outcome carrying blockers) — the earlier false-success defect
  is fixed and regression-proven. In-progress records that never reach a
  terminal outcome are crashed runs and fail-safe the next invocation.
- **State** (`state.SaveModel`): written only from verified post-change
  state (atomic 0600, schema-version guards against downgrade-overwrite),
  and only after re-discovery + final validation + convergence + the
  anti-laundering journal gate. `apply` never reads persisted state.
- **Backup/rollback**: transaction-scoped, manifest-bound
  (`<backup-root>/<tx>/<action>/`, content-first manifest-last, digests,
  verify-before/after restore); reverse-order rollback on any failure;
  `ROLLBACK_FAILED` (or failure on a no-autonomous-retry action) latches
  `RECOVERY_REQUIRED`.
- **Known residual ordering**: state persistence still happens **before**
  the deferred journal terminal record (`state persistence → journal
  COMPLETED`). This is an unresolved architectural/recovery concern (the
  designed journal-terminal-first ordering, HANDOFF 2026-09-27 §5.8): its
  effect is a safe-stop with a confusing diagnosis (state updated, journal
  says crashed), not an authority risk — under the claim-then-corroborate
  ownership design (§E/G) it can only downgrade ownership, never upgrade
  it.

## E. Current PURE foundations (implemented, tested, zero production
importers — none of them grants authority)

- **`internal/capability`** (C1/C2): closed five-capability vocabulary
  (`muvg.projectfile.v1`, `muvg.sysctl.apply.v1`, `muvg.routing.reserve.v1`,
  `muvg.firewall.tagged.v1`, `muvg.firewall.mssclamp.v1`) with compiled
  parameter schemas, byte-exact canonical parsing, typed derivation
  constructors, and conflict-rejecting aggregation. Compiled namespace
  constants: chains `vpsgw_`, tag `muvg` (provisional — operator decision
  L1). **Plan-to-capability mapping (C3) does not exist**; an audited
  project-file-only PURE slice is specified as ready (§J).
- **`internal/ownership`** (O1): closed 8-verdict vocabulary
  (UNDETERMINED > CONFLICT > COLLISION > GONE > OWNED_DRIFT > UNPROVEN >
  OWNED_VERIFIED > ABSENT), typed `ResourceIdentity` per class, compiled
  birthright namespaces, non-authoritative `StateEvidence`/`EvidenceRef`/
  `SpecHash` claim types. Legacy config labels (OWNED/EXTERNAL/UNKNOWN) are
  not verdicts and have no conversion path.
- **`internal/sysctl`** (S1–S4): bounded `/proc/sys` runtime reads over the
  compiled allowlist; strict persistence parsing of the ranked `sysctl.d`
  set plus the unranked `/etc/sysctl.conf` (explicit empirical-ordering
  uncertainty); per-key resolution. Strengthened in `10cdaac`: directory
  listing failures and sysctl.conf unsupported/unreadable states propagate
  as per-key uncertainty — a supported key can only resolve confidently
  when every source that could override it was successfully inventoried
  (UNKNOWN != absent). `EffectiveRPFilter` = max(all, interface), pinned.
- **`internal/leak`** (D1/D2): the pure direct-leak evaluator over typed
  RPDB inventories. Strengthened in `0bfb29e`: SAFE is bounded to the
  supported topology envelope — rules carrying unmodeled selector/action
  keys (iif, suppress_*, not, ...) refuse the walk; multipath (nexthop)
  routes are flagged and never reduced to a single device; multiple
  defaults must agree or the table is ambiguous; a competing more-specific
  route in the selected table blocks SAFE; route-get evidence is
  authoritative in both directions; TUN liveness is mandatory; scope is
  IPv4-path only; no loop-safety claim is ever emitted (LOOP_SAFE is a
  separate unbuilt family).

## F. What is NOT implemented

Generalized MUVG mutation (unreachable, §C); C3 plan-to-capability mapping
(specified, not written); exact signed capability-set verification (C4);
whole-plan composition admission (`MUVG_INTEGRATION_V1`/`MUVG_FILES_REFRESH_V1`
are design concepts); ownership admission (O2–O11); recovery v2 (per-action
durable progress, purpose-bound resolution — designed, see the recovery
paragraph below); approval v2 (purpose/domain fields) and its production
wiring; sysctl effective-state evaluator (S5) and any sysctl mutation;
direct-leak doctor integration (D3) and production semantics (D6/D7);
Mihomo/TUN correlation discovery (M1–M6) and AWG source-selector discovery
(A1–A6); firewall rule-level discovery and loop proof (F1–F12); deletion /
decommission authorization; adoption. Recovery purposes named in design
discussions — `ABANDON`, `COMPLETE_ROLLBACK`, `ACCEPT_CURRENT` — are **design
only**: there are no recovery CLI commands, and manual journal deletion is
NOT an authorized recovery protocol (root's OS ability to delete files is
execution capability, not application authorization).

## G. Current P1 blockers

- **P1-A (ownership admission) — CONTAINED LATENT.** Config (and, on the
  read-only dry-run path, persisted state) can assert OWNED labels that flow
  Model → Plan action → executor trust. Contained solely by the shape-pinned
  experiment guards + registry pins + the CLI tripwire; no host identity is
  checked anywhere (the Saymer3 restriction is operational, not compiled).
  Closure design (evidence corroboration against the durable journal, live
  derivation, admission matrix, state-v2 Evidence[] with no v1 migration
  into authority) is preserved in the 2026-09-28 design work; the first
  slice (O5-A) is specified in §J. Widening any guard before O5/O6 would
  convert self-declared ownership into mutation authority.
- **P1-B (recovery authorization) — CONTAINED LATENT.** The latch blocks
  every later mutation/persistence and nothing in code clears it; but no
  authorized resolution exists — resolution today means root manually
  deleting journal records, which is outside application semantics. Closure
  design (closed purpose vocabulary ABANDON/COMPLETE_ROLLBACK/ACCEPT_CURRENT,
  purpose-bound single-use authorization with domain separation, journal v2
  per-action durable progress, under-lock resolution orchestration) is
  preserved; the first slice (R4-B classifier over the existing v1 journal)
  is specified in §J.

## I. Widening moratorium (binding STOP boundary)

Generalized mutation authority must not be widened — do not remove or
loosen `firstExperimentGuard`/`fileExperimentGuard`, do not re-enable
`tools/fileexperiment` mutating execution (disabled as P1-A containment,
§C — re-enabling requires ownership provenance, an explicit operator
decision, and updating the `TestFileExperimentHasNoExecutePath` tripwire in

do not flip any `Defined: false` action kind, do not implement approval-v2
execution before G2/G4, do not import the PURE packages
(capability/ownership/leak/sysctl) into production paths, do not trust
`Model.Ownership` or plan ownership labels as admission input, do not clear
a recovery latch programmatically, and do not write sysctls/routes/firewall
rules outside a reviewed slice. Current blockers (from code): P1-A, P1-B,
C3 + typed Plan specs for sysctl/routing/firewall/MSS, exact capability-set
verification, composition admission, ownership admission, safety admission,
under-lock fresh capability re-derivation, executor-local hard policies for
the new classes, and recovery resolution semantics. Every blocker is a
designed-but-unimplemented layer; none is lifted by the overnight PURE
fixes or by the fileexperiment containment.

## J. Recommended next work

**First slice — O5-A, ownership evidence-verification primitive** (PURE,
no authority effect): new `internal/ownership/evidence.go` +
`evidence_test.go`. API: a minimal `TransactionView` interface (journal
read model — defined inside ownership, implemented later by an adapter),
a `LiveFact{Present, PresentProven, SpecHash}`, and
`Corroborate(claim StateEvidence, tx TransactionView, live LiveFact,
currentHost machineid identity) (Verdict, reasons)`: structural claim
validation → matching durable COMPLETED non-rolled-back transaction → host
legs (record vs current vs claim) → plan-fingerprint leg → spec-hash leg →
live legs → verdict ∈ {OWNED_VERIFIED, OWNED_DRIFT (files/drop-in),
CONFLICT (network), GONE, UNDETERMINED, UNPROVEN}. Every leg is required —
none is redundant. Why safe: pure functions, no I/O, consumed by nothing,
no latch interaction, no wiring. Must not do: read real /etc paths (facts
are injected), accept config/state labels as evidence, import the journal
package, or clear anything. Tests: the full corroboration matrix (host
mismatch, fingerprint mismatch, spec drift, live absent/unknown, missing/
crashed/rolled-back records, corrupt claims) — every case fail-closed.

**Ordered backlog**: (1) O5-A above; (2) O5-B live+evidence verdict
derivation per resource class; (3) R4-B recovery classifier over the v1
journal (makes the journal's insufficiency machine-readable); (4) C3-A
project-file-only PURE capability mapper (rejects every other action kind;
namespace predicate `/etc/vps-gateway/`, trust-dir excluded, deletion
rejected); (5) the deferred `--state` confinement fix on `apply` (remove
the flag exactly as `--lock` was removed — the last known current-path
